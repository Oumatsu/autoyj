# Products Overview i18n Design

## Scope

Localize all user-visible copy on the `/products` overview for Chinese and Amharic. Category pages and vehicle detail pages are outside this change.

Brand names, model identifiers, technical names, acronyms, numbers, currencies, and units remain source text where translation would reduce accuracy. Category names follow the existing navigation terminology.

## Current Problem

The page translates its section chrome with `products.*` keys but renders API-backed card fields directly. Consequently `name`, `tag`, `desc`, `label`, `tags`, and savings text can remain English after switching locale. Static fallback cards contain the same bypasses and can flash English before the API resolves.

## Translation Sources

Feishu's `I18n Locale` table remains the source of truth. Local TypeScript dictionaries are generated by `npm run sync:i18n`.

- Model names use `catalog.models.<slug>.displayName`.
- Card descriptions use `catalog.models.<slug>.cardHighlight`.
- Model-specific positioning uses `catalog.models.<slug>.cardTag` and `catalog.models.<slug>.cardLabel`.
- Reusable short values such as battery and range tags use `catalog.cardValues.<normalized-value>`.
- Savings formatting uses `products.*` placeholder keys instead of English string concatenation.

Existing `displayName` and `cardHighlight` translations are reused rather than duplicated.

## Frontend Data Flow

The overview converts each raw API or fallback product into localized display values before rendering:

1. Look up the slug-keyed model name and description.
2. Look up the slug-keyed tag and label.
3. Translate each reusable tag independently, preserving unknown technical values as a fallback.
4. Format savings through a locale template.
5. Use the localized name for visible headings and image alternative text.

English remains the final fallback when a translation is unavailable or malformed.

## Category Naming

The visible category headings match the navigation vocabulary:

- Chinese: `网约创收利器`, `商务行政旗舰`, `多功能商用先锋`.
- Amharic: values from `nav.revenueKing`, `nav.eliteFlagship`, and `nav.utilityPro`.

The existing split-color typography may divide a category into two translated fragments, but their concatenated text must equal the navigation label.

## Translation Policy

Translate prose and commercial meaning. Preserve brand names and source-backed identifiers such as Huawei, BYD, AITO, LiDAR, ADS 3.0, 800V, kW, km, and currency amounts. Amharic may retain a brand or model in Latin script when transliteration would be ambiguous.

## Failure Handling

Translation resolution must never throw when the dynamic translation response contains a non-string value. A missing or malformed translation falls back to the API value. Arrays are normalized before mapping.

## Testing

Add regression coverage proving that:

- the overview resolves all dynamic card fields through translation helpers;
- Chinese and Amharic dictionaries cover every featured model's name and description;
- model-specific card tags and labels are present where the API exposes them;
- reusable short tags are translated without translating brands, numbers, or units;
- category headings concatenate to the navigation terminology;
- no raw dynamic card description, tag, label, or tag array is rendered directly.

Run focused tests, the full Node test suite, `npm run check`, and a clean production build. Build-generated i18n differences are reviewed separately from source changes.
